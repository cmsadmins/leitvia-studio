# Import a post

Details for `leitvia-migrate` when the source is another WordPress site. The inventory, the mapping to content types and the reconciliation report of [external source](external.md) stay; only the translation and the images go into one call per post.

When the source is a WordPress site (WPBakery, Impreza or plain HTML), import each post, page or entry with `leitvia/import-post` instead of translating it yourself. Studio turns the HTML into core blocks, turns the text, links and images of WPBakery and Impreza shortcodes (`vc_row`, `vc_column`, `vc_column_text`, `vc_single_image`, `vc_btn`, `us_text`, `us_btn` and others with text) into blocks, keeps only the text of other shortcodes (registered here, of core, of a known page builder or form plugin, or with a closing tag or a quoted attribute; any other text in square brackets such as `[R=301,L]` or `[a-z]` stays, and nothing inside `pre` or `code` changes), loads the images of the source host into the media library once, rewrites links to the source host as paths and closes gaps in the heading levels.

- Input: `source` (the old address, the key of the import), `post_type`, `title`, `content` (the HTML of the post: `content.rendered` of the public REST API of the source, or the stored HTML with its shortcodes when the person hands you an export), `slug`, `date`, `status`, `author` (user ID, login or email of a user of this site) or, for an author without an account here, `author_name` (the name the old site showed; it becomes the author name and the Person of the structured data, no user is created; it holds on every import, so a second import adds or corrects it, and `leitvia/update-content` takes `author_name` too), `parent` or `parent_source` (old address of a parent imported before or waiting in the open package with the same `package` key; a parent nobody imported rejects the call with reason `parent_source` instead of a page at the top level, and a second import with `parent_source` moves a post under its parent), `terms`, `kind` for a page that is a legal text or another kind of `leitvia/compose-page` (`imprint`, `privacy`, `terms`, `withdrawal`, `accessibility`, `contact`, …; a legal kind keeps the import at suggest, so it waits in the package for a person), `featured_image` with `url` and `alt`, `seo` with `title` and `description`, and the `package` key of the migration. Images of a CDN need `media_hosts`; image shortcodes with attachment IDs of the old site need `images` (old ID to image address).
- First `dry_run: true` for the sample of three: `report.content` is the block markup, nothing is loaded or written. Compare it as in [translate](translate.md#compare-before-you-write).
- A second call with the same `source` updates the post it created; run the whole list again after a fix, nothing is doubled.
- Import parents before their children, and posts before the menu (`leitvia/update-navigation` with the new paths).
- FAQ parts become the block `leitvia/faq` with FAQPage structured data (`faq`, default `true`): after a heading such as "FAQ" or "Frequently asked questions" (also in German), each question as a heading one level below it or a paragraph all in bold (the answer after a line break in it or in the paragraphs and lists that follow), up to the next heading of the same level. `report.faq` counts the questions; check them in the dry run. `"faq": false` keeps headings and paragraphs, for example when the questions are no FAQ.
- Rendered HTML of a page builder or form plugin may hold scripts: `script`, `style`, `noscript`, `template` and `form` go with their content, `report.removed` counts them per tag. Rebuild a form with the form blocks of the site.
- `report`: `faq` (questions turned into the FAQ block), `media` (loaded or reused images with their IDs), `unmapped` (what did not carry over: shortcodes without text, images of other hosts), `dropped` (spacing and icons of the builder), `removed` (code elements), `headings` (moved levels), `missing_alt` (images that need an alt text, set it with `leitvia/set-alt-text`), `unlinked` (linked images without alt text: the image came without its link, the entry names the image and the address; give the image an alt text and set `href` with `leitvia/update-block`), `seo` (SEO texts of the live site outside 60 characters or 50 to 160, or with a figure the page does not say: kept as they were, correct them later with `leitvia/update-seo`; only a star rating that is not the confirmed one stays out), `links` (links turned into paths). Every entry of `unmapped`, `unlinked` and `seo` goes into the reconciliation report.
- A rejection of the checks (alt text, link text, heading) names the finding with `block` and `place` (block type and the start of its text or its image file): fix it in the source HTML you send, or write the post with `leitvia/create-content` from `report.content` of a dry run.
- A legal page that came in without `kind`, or exists already, such as the privacy policy page of WordPress: `leitvia/set-page-structure` or `leitvia/update-content` with `post` and `kind` (`""` clears it); never trash and recreate the page for it. `leitvia/audit-site` reports such pages as `leitvia/page-kind`.
