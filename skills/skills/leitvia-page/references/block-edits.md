# Block edits

Details for `leitvia-page`, `leitvia-maintain` and `leitvia-a11y`. Read this when a change goes beyond the text of a block.

- **A new link on words of a text:** `add_link` with `text` (the exact words of one run of text) and `url`, per block in `leitvia/update-block` or `leitvia/update-content`. Other links and inline formatting stay; the first place outside a link counts. `url` alone only changes the link a text has. A new text with a link in it: `text`, `link_text` (the linked words, part of `text`) and `url` in one edit, also in `insert`: `{ "block": "core/paragraph", "text": "Write to hello@example.org.", "link_text": "hello@example.org", "url": "mailto:hello@example.org" }`.
- **Words in a text with several links or `strong`:** `replace_text: { "find": "129 €", "with": "149 €" }` in `leitvia/update-block`, per block in `leitvia/update-content` or as an edit. Links, their targets and inline formatting stay; `text` is refused there with `leitvia_static_markup`. `find` must stand once and within one run of text: a price in `strong` with words around it is replaced in two edits, the part inside on its own. A space in `find` also finds a protected one (`&nbsp;`, U+00A0, U+202F) that sites keep before `€` or after "from" and that `get-block` shows as a space. Not together with `text`.
- **Repeated writes into one open package** (`package` key): the second write on the same post is checked against the state the package leaves, not against the saved page. A rerun of the same `replace_text` then fails with "does not contain find" and the message names the package (`data.package_key`). Read that state with `leitvia/get-package`, or apply or discard the package before a rerun.
- **Remove an attribute:** `attributes: { "<name>": null }` puts it back to the default of the block, such as `{ "line": null }` on a block that should follow `skus` only. Not for `sizeSlug` and `linkDestination` of an image.
- **Edits after a `remove`:** the edits of `leitvia/compose-page`, `leitvia/replace-pattern`, `leitvia/insert-section` and `leitvia/update-template-part` apply in order, and a `remove` moves every later block of the same parent up one place: `p:0.0.1` then names the block that was `p:0.0.2`. Edit the later blocks first and remove last, or count from the new order ([composition](composition.md)). A text edit that lands on a block without text, such as `core/buttons`, is refused with `leitvia_invalid_input` and reason `text`; read the outline again instead of inserting the pattern anew.
- **Publish a draft:** `leitvia/update-content` with `status: "publish"` and the `package` key, like any change. At a level below `autonomous` it waits for a person. `future` needs a `date` in the future; without a date of its own the post gets the date of publishing.
- **Text attributes of static blocks:** `leitvia/update-block` with `attributes` changes prefix, value, suffix and label of `leitvia/counter`, and any text attribute whose element the block has. An optional part that is empty, other than on the counter, is refused with `leitvia_static_markup`.
- **Ground of a light section:** `attributes: { "backgroundColor": "surface-alt" }` on the outer `core/group` of a section whose ground is light: `surface`, `surface-alt` or an extra surface of the token set (`surface-extra-<name>`, such as the panel of a menu), `null` removes it. Use it when two neighbors would share a tone. A dark band is `attributes: { "className": "is-style-inverse" }`; other grounds come with another pattern.
- **Size of a heading or paragraph:** `attributes: { "fontSize": "<slug>" }` with a font size of `leitvia/get-tokens`, `null` for the size of the theme. The rejection lists the slugs. The same on a `core/quote` makes the quotes of a row equal. An h1 in `display` in the first section of a page with a button shrinks with the window height (not below `heading-l`, about 68 px at 1440 × 900), so the button stays in the first screen; a page title without a button in its first section keeps the full `display`. For a big title, keep the button out of the first section. On narrow windows `display` and `heading-l` grow no larger than an eighth of the window (12.5vw), so a single long word of about ten capitals ("CONSULTING") stays whole at 390 and 320 px; nothing to set. An e-mail address or URL as link text (`add_link` with `mailto:` or `https://`) breaks after `@` and `/` and before a dot, never with a hyphen, and a paragraph that holds the address link alone puts "hello@" over the domain; keep the address as the whole link text, not split over two links or with spaces, and a large size such as `heading-m` stays possible.
- **A title larger than display:** `attributes: { "className": "is-style-display-xl" }` on a heading in `display` or without a size: a third larger (7.5rem becomes 10rem), for the h1 of a title section without a button or a claim of one to three words, once per page. On narrow windows it keeps the cap of 12.5vw, in a column at most an eighth of the column (so a word of up to 11 letters never breaks inside; in half a row at 1440 px about 100 px), in the first screen of a page with a button it stays at display. For the full 10rem the title needs a column of 80rem, that is the whole content width without columns. The same column cap holds for every heading in `display`; longer words hyphenate by the page language.
- **Font of a heading or paragraph:** `attributes: { "fontFamily": "mono" }` with a font role of the theme (`body`, `heading`, `mono`, `ui`), `null` for the font of the block; such as a number `01` or a greeting in mono.
- **Alignment of a heading or paragraph:** `attributes: { "textAlign": "center" }` (`left`, `center`, `right`, `null` removes it), also in `insert`: `{ "block": "core/heading", "text": "Contact", "attributes": { "textAlign": "center" } }`, so a heading added to a centred hero stays centred.
- **One word in italics:** `emphasis` with the exact words, such as `{ "block": "p:0.1", "text": "We make good work easy to find.", "emphasis": "good" }`. The first place outside a link and outside italics counts, else the first inside a link, so a title linked as a whole takes `emphasis` with its full text; within one run of text, links and other formatting stay. `text` in the same edit comes first, a later `text` alone drops the italics again. A button label takes it too, such as `TOUCH` of `GET in TOUCH` on a shape button. The italic words in another font role, such as the grotesque italic in a serif heading: `"emphasis": { "text": "your", "font": "ui" }`.
- **Words struck through:** `strike` with the exact words, found like `emphasis`, such as a phrase a claim takes back: `{ "block": "p:0.1.0", "text": "Less Bla Bla, more doing", "emphasis": "Bla Bla,", "strike": "Bla Bla," }` gives italics struck through.
- **A few words in another font, color or size:** `mark` with `text` and at least one of `font` (body, heading, mono, ui), `color` (ink, ink-muted, accent) and `size` (a font size of `leitvia/get-tokens`), found like `emphasis`. A small number before the words of a title, on its baseline: `{ "block": "<h1>", "text": "01Consulting", "mark": { "text": "01", "font": "mono", "color": "accent", "size": "heading-l" } }`, one heading and no number paragraph above it. Quotation marks in the accent: one edit each with `"mark": { "text": "“", "color": "accent" }` and with the closing mark.
- **Menu button on every width and colors of the open menu:** on a `core/navigation` (also in the `edits` of `leitvia/update-template-part`) `attributes: { "overlayMenu": "always", "overlayBackgroundColor": "surface-extra-mint", "overlayTextColor": "ink" }`; `overlayMenu` `never`, `mobile` (the default) or `always`, colors from `surface`, `surface-alt`, `ink`, `accent`, `on-accent` or an extra surface of the set. `hasIcon: false` shows the word Menu instead of the icon, `icon` `handle` or `menu`; `text` on the `core/navigation` (`{ "block": "<navigation>", "text": "MENU" }`, up to 30 characters) puts its own word on the button and switches the icon off. A menu that opens the part `navigation-overlay` (header patterns of the theme) refuses the overlay colors, core ignores them there: give the outer group of that part `backgroundColor` with `leitvia/update-template-part`, part `navigation-overlay`, such as `{ "block": "p:0", "attributes": { "backgroundColor": "surface-extra-mint" } }`.
- **Text and link of a menu item:** `text` and `url` on a `core/navigation-link` or `core/navigation-submenu`, such as `{ "block": "p:0.0.1.2", "text": "Imprint", "url": "/imprint/" }` in the edits of a footer; a new url makes it a custom link. The menu itself is `leitvia/update-navigation`.
- **Line break in a text:** a new line or `<br>` in `text` (paragraph, heading, list item, button, also in `insert`) becomes a `br`, such as `"Brand
your
Story"` for a claim over three lines; any other markup stays text.
- **Width of a column:** `attributes: { "width": "66.66%" }` on a `core/column`, in percent, `null` to share the free space; set every column of the row in the same call, such as `33.33%` and `66.66%`. A large centred graphic: the column with the graphic wide (`75%`), the other narrow, or the two side by side at `50%`.
- **Vertical alignment of columns:** `attributes: { "verticalAlignment": "bottom" }` on a `core/columns` (`top`, `center`, `bottom`) or on one `core/column` (also `stretch`), `null` removes it: the intro beside a large title at the height of its last line (`bottom`), a heading in the middle beside a graphic (`center`).
- **Size of a button:** `attributes: { "fontSize": "body" }` on a `core/button`, `null` for the size of the theme; a shape button (`is-style-shape-triangle`, `is-style-shape-circle`) grows with it as a whole (`meta` about 9.5rem, `body` about 13rem wide, without about 7.5rem). Its label keeps the case it is written in, such as `"GET
in
TOUCH"`.
- **Image to the edge of the window:** in `content-text-media` (or any section with a `core/columns` beside an image) `attributes: { "align": "full" }` on the `core/columns` (`p:0.0`): the image column bleeds to the window edge, the text column keeps the edge of the content; `is-style-media-right` turns it to the right edge. The crop of the image is `aspectRatio` on its `core/image` (`"4/3"`, `"3/4"`, `"16/9"`, `null` for the whole image) instead of the square of the pattern.
- **Image fills its cell:** add `is-style-media-fill` to the full-width `core/columns` of `content-text-media`, `{ "block": "p:0.0", "attributes": { "align": "full", "className": "is-style-media-fill" } }` (with `is-style-media-right` space separated for the image on the right): from tablet width the image covers its column from the top to the bottom of the section, flush with the sections around it and without a gap to the text, and the widths of the columns count exactly (`58.33%` image, `41.67%` text). The text keeps the padding of the section; on phones the image keeps its crop. Sections from before this style keep their markup: set the class with `leitvia/update-block` on their columns.
- **Index list (title left, text with links right, a line between rows):** `content-two-columns` with the widths `33.33%` and `66.66%` on its two columns, a `core/heading` inserted in the first column in place of its paragraphs, `level` 3 only when the section has an h2 above the index, otherwise `level` 2 (on a page whose only heading above is the H1 of the title section an h3 would skip a level), links with `add_link`; one row per entry with `repeat` on the `core/columns`, a `core/separator` inserted before each copy with `"attributes": { "className": "is-style-wide", "align": "wide" }` (without `align` it stays at the width of the content, narrower than the columns). With an icon above each title: `{ "block": "p:0.2.0.0", "insert": { "block": "leitvia/icon", "attributes": { "icon": "<name>", "size": "xx-large" } }, "position": "before" }` once the title stands first in the column, before the `repeat`: 96 px suit an index list with a third of the width for icon and title; `x-large` (80 px) for a narrow first column, `large` (64 px) for cards and tiles.
- **Marquee in a band:** an inserted `leitvia/marquee` spans the full width (`align` `full`, the Pause button at the edge of the content, the line runs out to the window edge); `attributes: { "align": "wide" }` or `null` narrows it. Its statements take `fontSize` and `fontFamily` on the marquee (`"attributes": { "fontSize": "heading-m", "fontFamily": "heading" }`), and `className` `is-style-lines` sets it between two thin lines with a `//` in the fill accent after each statement (in the text color on an accent or other colored ground) and the Pause button as a small symbol (still a button named Pause), the moving line fading in beside it; `is-style-lines-caps` does the same in capitals with letter spacing. As the first or last block of a full width section a full width band sits on that edge of the section, no padding before or after it. The statements are a `core/list` in `inner`, one `core/list-item` with `text` each, without slashes of their own.
- **Color of a heading or paragraph:** `attributes: { "textColor": "accent" }`, also `ink` or `ink-muted`, `null` for the color of the section; such as a card title in accent.
- **Icon color and size:** `attributes: { "textColor": "accent", "fontSize": "heading-m" }` on `leitvia/icon` or `leitvia/icon-list`; the icon is 1em of the size (`heading-m` about 32 px, `heading-l` about 40 px). A large icon that heads an entry: `size` `large` (64 px, cards and tiles), `x-large` (80 px) or `xx-large` (96 px, index lists) on `leitvia/icon`, whatever the font size; `null` for 1em.
- **Height of a cover:** `attributes: { "minHeight": 90 }` on a `core/cover`, in vh from 30 to 100, `null` for the height of its content.
- **Focal point of a cover photo:** `attributes: { "focalPoint": { "x": 0.5, "y": 0.3 } }` on a `core/cover`, each from 0 (left, top) to 1 (right, bottom): the part of the photo that stays in view where the cover crops it, as on phones, where a stage is tall and narrow. Set it on the subject of the photo, `null` for the middle.
- **A block the pattern lacks, or another order inside a section:** an edit with `insert` adds a block after the one named, with `position: "before"` ahead of it; `insert` takes `core/paragraph`, `core/heading`, `core/separator`, `core/site-logo`, `core/image` (with `image`: `{ "block": "core/image", "image": { "id": 12, "alt": "Logo mark" }, "attributes": { "width": "3rem" } }`, such as the logo mark in the foot of a menu), `core/buttons` and `core/button` besides the catalog, with `text` and `attributes` (`className`, `level`). A button below a table: `{ "block": "<table>", "insert": { "block": "core/buttons", "inner": [ { "block": "core/button", "text": "Ask for a server", "url": "/contact/" } ] } }`; a second one gets `"attributes": { "className": "is-style-outline" }`, a button alone needs `text` and `url`. An eyebrow above a heading: `{ "block": "<heading>", "insert": { "block": "core/paragraph", "text": "Services", "attributes": { "className": "is-style-eyebrow" } }, "position": "before" }`. `move` with the ID of a sibling moves a block next to it (`position` after or before). Each is an edit of its own; IDs after it shift. A section takes up to 250 edits. A list with any number of entries: `insert` of `leitvia/icon-list` with `inner` (one `leitvia/icon-list-item` with `text` each), or `repeat` on one entry or card and edits of the copies.
- **Tables:** `table` with `head` (column headers, optional: a `core/table` without it has no header row, a `leitvia/comparison-table` keeps its own), `rows` (each as long as `head`, or as the first row) and for `core/table` `foot` fills every cell as plain text, on `core/table` (such as in `content-price-list`, `content-comparison`) and on `leitvia/comparison-table`, also in `insert`. Column headers get `scope="col"`, the first cell of a row becomes its row header (`row_headers: false` for none). Put the caption in `caption` of the same edit; a table of a pattern section filled without one (compose-page, insert-section, replace-pattern) loses the sample caption of the pattern, and a `leitvia/comparison-table` inserted without one has no caption (none of the English sample text of its example), so name it after the section. Core tables scroll inside a focusable region at 390 px, the comparison table turns into cards. In the block style `is-style-comparison` only columns of figures and prices align to the end, columns of words stay at the start; no alignment per cell needed.
- **Cells with lines:** `attributes: { "className": "is-style-grid-net" }` on the grid of a teaser section (`teaser-services` `p:0.1`, a grid of two groups of two, counts as one grid of four cells; `columns` 2 for two by two, 3 for three across): the entries stand as cells with 1 px lines between them, and a cell with a link turns into the fill accent of the token set while the pointer rests on it or its link has focus; the whole cell is the target of its link, so give each cell one link (title or "more" link, not both). The fill covers the whole cell between its lines, every text and number on it takes the text color of the fill and no link is underlined there; images and blocks with a ground of their own stay as they are. `align` `full` on the grid lets the lines reach the window edges; a full width net that is the first or last block of its section meets the section above or below without padding (remove an intro heading before it for that). `columns` 3 lowers the minimum column width of the pattern (31rem) to 21.33rem, so three cells stand side by side from about 1024 px; set `columns` again on grids built before this change. **Rows with lines:** `is-style-grid-rows` instead of `is-style-grid-net`: one cell per row across the full width, the blocks of a cell side by side (number, title, short text), below 782 px the third block goes under the first two; hover, focus and lines as in the net.
- **Quote over the wide width:** `attributes: { "align": "wide", "fontSize": "heading-l" }` on the `core/quote` of `content-quote` (`p:0.0`): it leaves the narrow column of the section for the wide width. Quotation marks in the accent with `mark` (above).
- **List with lines between the entries:** `{ "block": "<paragraph>", "insert": { "block": "core/list", "attributes": { "className": "is-style-divided" }, "inner": [ { "block": "core/list-item", "text": "Graduate of the school of journalism" } ] } }`, one item per entry in `inner`; `is-style-checklist` for ticks.
- **Headings that are a link on dark pages and bands:** a heading whose whole text is one link (a service title, a cross link) reads in the text color without underline on a dark page or band and shows the accent and the underline on hover and focus; nothing to set. A link inside the words of a heading keeps its underline.
- **No breadcrumbs on one page:** `leitvia/set-page-structure` with `breadcrumbs: false` and the hash of the outline hides the breadcrumbs of the template on that page, with their BreadcrumbList; `true` shows them again. For pages whose title section stands right below the header in the design.
- **Two block styles on one block:** `className` takes up to three styles that combine, space separated, such as `"is-style-sticky-header-desktop is-style-overlay-header"` on the header group. `overlay-header` sticks like every header; `sticky-header` is the default and needs no class.
- **Columns of a gallery:** `columns` 1 to 6 on the `core/gallery` block, as on a grid.
- **Name for screen readers:** `attributes: { "label": "..." }` on a slider, an announcement bar or the accessibility bar changes the `aria-label` in their markup. Write it in the language of the page.
- **Posts per page of a list:** `leitvia/update-block` on the `core/query` block with `attributes: { "query": { "perPage": 6 } }`. Keys you leave out stay. `perPage` counts with `inherit` false.
- **A new section on a page that exists:** `leitvia/insert-section` with `post`, `sections` (each `pattern` and `edits` as in `leitvia/compose-page`, with the same checks) and one place: `after` or `before` with a top-level ID from the outline, or `position` `start` or `end`; without a place the sections go to the end. An anchor must be unique on the whole page.
- **A hero for a page that exists, with the template page:** `leitvia/insert-section` with the hero in `sections`, `position: "start"` and `template: "page-landing"` in one call. The hero carries the h1 and the new template prints no title, so the page keeps exactly one h1; the other blocks stay as they are. Never `compose-page` with `post` for this when the page holds blocks of other plugins.
- **A block of another plugin in a section:** `leitvia/insert-section` with `wrap: { "block": "<top-level ID>", "ground": "surface-alt", "heading": "Book a call" }` puts a top-level block (a shortcode, a form or calendar of a plugin) unchanged into a section at its place: full width, the spacing of a section, ground `surface` (default), `surface-alt` or `inverse`, and an optional h2 at the wide edge, where the headings of the patterns start. No place with `wrap`.
- **Another order of sections:** `leitvia/insert-section` with `move` (top-level ID of the section) and the place, one call per section; read the outline again in between, path IDs shift.
- **Take a section out:** `leitvia/remove-section` with `block`. The last section of a post stays; `leitvia/rollback` of the package brings a section back. A heading after it that now skips a level (an h4 after its h3 went) is a warning naming the heading and its level, not a rejection: take out its subsections as well, from the last to the first, or change its level.
- **Questions and answers into an FAQ:** `leitvia/insert-section` with `faq: { "from": "<first ID>", "to": "<last ID>", "heading": "Questions and answers", "intro": "" }` turns a range of top-level blocks into one `leitvia/content-faq` at its place, in one call. A question is a heading, a paragraph that starts with a bold question (the rest of it starts the answer) or a short paragraph of its own ending in `?`; the blocks up to the next question are its answer and keep code, bold, italics and links. The range starts with a question, and every question needs an answer. No place with `faq`.
- **Another pattern for a section:** `leitvia/replace-pattern` with `block` (a top-level ID from the outline), `pattern` and `edits` as in `leitvia/compose-page`. Texts and button links of the old section move over first, the edits win; `carry: false` keeps the texts of the pattern. A section of entries (services, steps, tiles) moves over entry by entry with links and icons, as many entries as before ([sections with icons](icon-sections.md)); without `pattern` a section gets the `successor` of its pattern. Set an anchor again with an `anchor` edit.
- **Page under another page:** `parent` of `leitvia/update-content`, `0` for the top level. It changes the address like a slug; point old links to it with `leitvia/repair-links` and `from` and `to`.
- **Remove a page or post:** `leitvia/trash-content`. It always waits for a person and stays restorable; no ability deletes for good, the person empties the trash. Refused for the front page, the posts page, the privacy page and a page with subpages; `notice` names the pages that link to it.
- **Map (`leitvia/map`):** set `lat`, `lng`, `zoom` (1 to 19), `height`, `heading`, `linkText` and `markers` (each `title`, `address`, `lat`, `lng`) as `attributes` of `insert` or of `leitvia/update-block`; the list of places is built again. `markers` replaces the list, so send it on every insert, or the sample place stays. `text` is the heading.
- **Bound values (`bind`):** an edit or a block of `insert` takes `bind`, per attribute a registered source with its `args`, written to `metadata.bindings`: `"bind": { "content": { "source": "core/post-data", "args": { "field": "date" } } }`; `null` removes a binding. Sources and bindable attributes are under `bindings` of `leitvia/get-content-model`; add-ons add sources, such as the price of a product. Send `text` along as the saved fallback.
- **Bound button:** a button whose `url` a binding fills (`metadata.bindings.url`, for example the button of a job posting) takes no new link. `url: ""` removes only its saved link, the binding stays; change the value at its source.
- **Library image:** `image` `{ id }` without `alt` keeps the alt text of the library; `decorative: true` for decoration.
- **Caption:** `caption` on `leitvia/update-block` or per block in `leitvia/update-content`, plain text, on images, videos, audio, galleries, tables and embeds. An empty string removes it.

## Captions of a video

A video with speech needs captions (WCAG 1.2.2):

1. `leitvia/add-media` with `data` (Base64) and `filename` ending in `.vtt`: UTF-8, first line `WEBVTT`. No alt text. It needs the right to upload files, and the result gives the attachment ID in `target.post`; in a package, in `applied.post` of `leitvia/get-package` once it is applied.
2. `leitvia/update-block` on the `core/video` block with `attributes: { "tracks": [ { "id": <attachment>, "kind": "captions", "srclang": "de", "label": "Deutsch" } ] }`. The list replaces the tracks of the video, an empty list removes them. Only WebVTT files of the library count.

The file must lie on this site, or browsers do not load it.
